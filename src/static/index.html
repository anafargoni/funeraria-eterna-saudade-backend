Funerais

Rotas responsáveis pelo gerenciamento dos funerais.

GET /funeral
Listar funerais

Retorna todos os funerais cadastrados.

Parâmetros:

Não possui.

Restrições:
  • É necessário existir pelo menos um funeral cadastrado.
Exemplo de retorno em caso de sucesso:
{ "msg": "Funerais encontrados!", "Funerais": [ { "id": 1, "duracao": 4, "data_evento": "2026-09-10", "local": "Cemitério Nossa Senhora do Carmo", "nome_falecido": "José Otavio", "data_nascimento_falecido": "1950-05-12", "data_morte_falecido": "2026-09-08", "cpf_falecido": "11122233344", "cpf_cliente": "12345678901", "pagamento": true } ] }
GET /funeral/:id
Buscar funeral por ID

Retorna um funeral específico através do ID.

Parâmetros:
  • id : ID do funeral na própria rota.
Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O funeral informado deve existir.
Exemplo de retorno em caso de sucesso:
{ "msg": "Funeral encontrado!", "data": { "id": 1, "duracao": 4, "data_evento": "2026-09-10", "local": "Cemitério Nossa Senhora do Carmo", "nome_falecido": "José Otavio", "data_nascimento_falecido": "1950-05-12", "data_morte_falecido": "2026-09-08", "cpf_falecido": "11122233344", "cpf_cliente": "12345678901", "pagamento": true } }
POST /funeral
Adicionar funeral

Cadastra um novo funeral e associa o funeral a um cliente através do cpf_cliente .

Parâmetros do corpo obrigatórios:
  • duracao : duração do funeral; deve representar um número inteiro maior que zero.
  • data_evento : data do funeral.
  • local : local do funeral.
  • nome_falecido : nome do falecido.
  • data_nascimento_falecido : data de nascimento do falecido.
  • data_morte_falecido : data da morte do falecido.
  • cpf_falecido : CPF do falecido.
  • cpf_cliente : CPF do cliente responsável pelo funeral.
  • pagamento : valor booleano ( true ou false ).
Parâmetros do corpo opcionais:

Não possui.

Restrições:
  • A duração deve ser um número inteiro maior que zero.
  • O local deve ser texto não vazio e ter no máximo 60 caracteres.
  • O nome do falecido deve ser texto não vazio e ter no máximo 30 caracteres.
  • As datas devem ser válidas; no banco, não podem ser anteriores a 01/01/1900.
  • A data de nascimento do falecido não pode ser posterior à data da morte.
  • A data da morte não pode ser posterior à data do funeral.
  • Os CPFs podem ser informados com ou sem pontos e hífen, mas devem resultar em exatamente 11 dígitos numéricos.
  • O CPF do cliente deve pertencer a um cliente já cadastrado.
  • Não é permitido cadastrar dois funerais com o mesmo CPF de falecido.
  • Pagamento deve ser obrigatoriamente booleano.
Exemplo de requisição:
{ "duracao": 4, "data_evento": "2026-10-05", "local": "Cemitério Municipal", "nome_falecido": "Marta Pereira", "data_nascimento_falecido": "1958-04-11", "data_morte_falecido": "2026-10-03", "cpf_falecido": "111.333.555-77", "cpf_cliente": "123.456.789-01", "pagamento": true }
Exemplo de retorno em caso de sucesso:
{ "msg": "Funeral adicionado com sucesso!", "data": { "id": 11, "duracao": 4, "data_evento": "2026-10-05", "local": "Cemitério Municipal", "nome_falecido": "Marta Pereira", "data_nascimento_falecido": "1958-04-11", "data_morte_falecido": "2026-10-03", "cpf_falecido": "11133355577", "cpf_cliente": "12345678901", "pagamento": true } }

Editar funeral

Edita todos os dados de um funeral já cadastrado. Também permite alterar o cliente associado através do cpf_cliente .

Parâmetros:
  • id : ID do funeral que será editado.
Parâmetros do corpo obrigatórios:
  • duracao : duração do funeral; deve representar um número inteiro maior que zero.

  • local : local do funeral.
  • nome_falecido : nome do falecido.
  • data_nascimento_falecido : data de nascimento do falecido.
  • data_morte_falecido : data da morte do falecido.
  • cpf_falecido : CPF do falecido.
  • cpf_cliente : CPF do cliente responsável pelo funeral.
  • pagamento : valor booleano ( true ou false ).
Parâmetros do corpo opcionais:

Não possui.

Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O funeral informado deve existir.
  • A duração deve ser um número inteiro maior que zero.
  • O local deve ser texto não vazio e ter no máximo 60 caracteres.
  • O nome do falecido deve ser texto não vazio e ter no máximo 30 caracteres.
  • As datas devem ser válidas; no banco, não podem ser anteriores a 01/01/1900.
  • A data de nascimento do falecido não pode ser posterior à data da morte.
  • A data da morte não pode ser posterior à data do funeral.
  • Os CPFs podem ser informados com ou sem pontos e hífen, mas devem resultar em exatamente 11 dígitos numéricos.
  • O CPF do cliente deve pertencer a um cliente já cadastrado.
  • O CPF do falecido não pode estar associado a outro funeral.
  • Pagamento deve ser obrigatoriamente booleano.
Exemplo de requisição:
{ "duracao": 4, "data_evento": "2026-10-05", "local": "Cemitério Municipal", "nome_falecido": "Marta Pereira", "data_nascimento_falecido": "1958-04-11", "data_morte_falecido": "2026-10-03", "cpf_falecido": "111.333.555-77", "cpf_cliente": "123.456.789-01", "pagamento": true }
Exemplo de retorno em caso de sucesso:
{ "msg": "Funeral atualizado com sucesso!", "data": { "id": 1, "duracao": 4, "data_evento": "2026-10-05", "local": "Cemitério Municipal", "nome_falecido": "Marta Pereira", "data_nascimento_falecido": "1958-04-11", "data_morte_falecido": "2026-10-03", "cpf_falecido": "11133355577", "cpf_cliente": "12345678901", "pagamento": true } }
DELETE /funeral/:id
Deletar funeral

Remove um funeral pelo ID.

Parâmetros:
  • id : ID do funeral que será removido.
Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O funeral informado deve existir.
  • Ao remover o funeral, as associações dele com serviços também são removidas pelo banco.
Exemplo de retorno em caso de sucesso:
{ "msg": "Funeral deletado com sucesso!", "data": { "id": 1, "duracao": 4, "data_evento": "2026-09-10", "local": "Cemitério Nossa Senhora do Carmo", "nome_falecido": "José Otavio", "data_nascimento_falecido": "1950-05-12", "data_morte_falecido": "2026-09-08", "cpf_falecido": "11122233344", "cpf_cliente": "12345678901", "pagamento": true } }

Serviços

Rotas responsáveis pelo gerenciamento dos serviços.

GET /servico
Listar serviços

Retorna todos os serviços cadastrados, ordenados pelo ID.

Parâmetros:

Não possui.

Restrições:
  • É necessário existir pelo menos um serviço cadastrado.
Exemplo de retorno em caso de sucesso:
{ "msg": "Serviços encontrados!", "quantidade": 10, "data": [ { "id": 1, "valor": "500.00", "descricao": "Preparação e conservação do corpo para o velório.", "nome": "Tanatopraxia" }, { "id": 2, "valor": "300.00", "descricao": "Preparação estética e cuidados com a aparência do falecido.", "nome": "Tanatoestética" } ] }
GET /servico/:id
Buscar serviço por ID

Retorna um serviço específico através do ID.

Parâmetros:
  • id : ID do serviço.
Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O serviço informado deve existir.
Exemplo de retorno em caso de sucesso:
{ "msg": "Serviço encontrado!", "data": { "id": 1, "valor": "500.00", "descricao": "Preparação e conservação do corpo para o velório.", "nome": "Tanatopraxia" } }
POST /servico
Adicionar serviço

Cadastra um novo serviço.

Parâmetros do corpo obrigatórios:
  • nome : nome do serviço.
  • valor : valor do serviço.
Parâmetros do corpo opcionais:
  • descricao : descrição do serviço; se não for informada ou ficar vazia após o tratamento, será armazenada como null .
Restrições:
  • O nome deve ser texto não vazio, possuir no máximo 35 caracteres e não pode repetir o nome de outro serviço, desconsiderando maiúsculas e minúsculas.
  • O valor pode ser informado como número ou texto numérico, mas deve estar entre 0,01 e 999999,99.
  • A descrição, quando informada, deve ser texto e ter no máximo 100 caracteres.
Exemplo de requisição:
{ "nome": "Preparação especial", "valor": 750.0, "descricao": "Serviço especial de preparação do falecido." }
Exemplo de retorno em caso de sucesso:
{ "msg": "Serviço adicionado com sucesso!", "data": { "id": 11, "valor": "750.00", "descricao": "Serviço especial de preparação do falecido.", "nome": "Preparação especial" } }

Editar serviço

Edita os dados de um serviço já cadastrado.

Parâmetros:
  • id : ID do serviço que será editado.
Parâmetros do corpo obrigatórios:
  • nome : nome do serviço.
  • valor : valor do serviço.
Parâmetros do corpo opcionais:
  • descricao : descrição do serviço; se não for informada ou ficar vazia após o tratamento, será armazenada como null .
Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O serviço informado deve existir.
  • O nome deve ser texto não vazio, possuir no máximo 35 caracteres e não pode repetir o nome de outro serviço, desconsiderando maiúsculas e minúsculas.
  • O valor pode ser informado como número ou texto numérico, mas deve estar entre 0,01 e 999999,99.
  • A descrição, quando informada, deve ser texto e ter no máximo 100 caracteres.
Exemplo de requisição:
{ "nome": "Preparação especial", "valor": 750.0, "descricao": "Serviço especial de preparação do falecido." }
Exemplo de retorno em caso de sucesso:
{ "msg": "Serviço editado com sucesso", "data": { "id": 1, "valor": "750.00", "descricao": "Serviço especial de preparação do falecido.", "nome": "Preparação especial" } }
DELETE /servico/:id
Deletar serviço

Remove um serviço pelo ID.

Parâmetros:

Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O serviço informado deve existir.

Clientes

Rotas responsáveis pelo gerenciamento dos clientes.

GET /cliente
Listar clientes

Retorna todos os clientes cadastrados.

Parâmetros:

Não possui.

Restrições:
  • É necessário existir pelo menos um cliente cadastrado.
Exemplo de retorno em caso de sucesso:
[ { "cpf": "12345678901", "nome_primeiro": "João", "nome_sobrenome": "Silva", "endereco_cep": "13560000", "endereco_rua": "Rua das Flores", "endereco_cidade": "São Carlos", "endereco_bairro": "Centro", "endereco_numero": 120, "contato_email": "joao.silva@email.com", "contato_telefone": "16999990001", "data_nascimento": "1985-03-15" } ]
GET /cliente/:cpf
Buscar cliente por CPF

Retorna um cliente específico através do CPF.

Parâmetros:
  • cpf : CPF do cliente na própria rota.
Restrições:
  • O CPF deve ser informado como texto válido e resultar em exatamente 11 dígitos após remover pontos e hífen.
  • O cliente informado deve existir.
Exemplo de retorno em caso de sucesso:
{ "cpf": "12345678901", "nome_primeiro": "João", "nome_sobrenome": "Silva", "endereco_cep": "13560000", "endereco_rua": "Rua das Flores", "endereco_cidade": "São Carlos", "endereco_bairro": "Centro", "endereco_numero": 120, "contato_email": "joao.silva@email.com", "contato_telefone": "16999990001", "data_nascimento": "1985-03-15" }
POST /cliente
Adicionar cliente

Cadastra um novo cliente.

Parâmetros do corpo obrigatórios:
  • cpf : CPF do cliente.
  • nome_primeiro : primeiro nome do cliente.
  • nome_sobrenome : sobrenome do cliente.
  • contato_email : email do cliente.
  • contato_telefone : telefone do cliente.
Parâmetros do corpo opcionais:
  • endereco_CEP : CEP do endereço.
  • endereco_rua : rua do endereço.
  • endereco_cidade : cidade do endereço.
  • endereco_bairro : bairro do endereço.
  • endereco_numero : número do endereço.
  • data_nascimento : data de nascimento do cliente.
Restrições:
  • O CPF deve ser informado como texto; pontos e hífen são removidos e o resultado deve possuir exatamente 11 dígitos. O CPF não pode estar cadastrado para outro cliente.
  • Nome e sobrenome devem ser textos não vazios; nome com no máximo 20 caracteres e sobrenome com no máximo 30.
  • O email deve ser texto, possuir @ e ponto, não começar ou terminar com @ , ter no máximo 40 caracteres e ser único.
  • O telefone deve ser texto; parênteses, espaços e hífen são removidos e o resultado deve possuir 10 ou 11 dígitos.
  • O CEP é opcional; quando informado, deve ser texto e resultar em exatamente 8 dígitos após remover o hífen.
  • Rua, cidade e bairro são opcionais e devem ser textos; limites de 40, 30 e 30 caracteres, respectivamente.
  • O número do endereço é opcional; quando informado, deve ser um número inteiro maior que zero.
  • A data de nascimento é opcional; quando informada, não pode ser anterior a 01/01/1900 nem estar no futuro.
Exemplo de requisição:
{ "cpf": "111.444.777-35", "nome_primeiro": "Mariana", "nome_sobrenome": "Pereira", "endereco_CEP": "13560-000", "endereco_rua": "Rua das Acácias", "endereco_cidade": "São Carlos", "endereco_bairro": "Centro", "endereco_numero": 50, "contato_email": "mariana.pereira@email.com", "contato_telefone": "(16) 99999-0011", "data_nascimento": "1994-06-20" }
Exemplo de retorno em caso de sucesso:
{ "msg": "Cliente adicionado com sucesso!", "data": { "cpf": "11144477735", "nome_primeiro": "Mariana", "nome_sobrenome": "Pereira", "endereco_cep": "13560000", "endereco_rua": "Rua das Acácias", "endereco_cidade": "São Carlos", "endereco_bairro": "Centro", "endereco_numero": 50, "contato_email": "mariana.pereira@email.com", "contato_telefone": "16999990011", "data_nascimento": "1994-06-20" } }

DELETE /cliente/:cpf
Deletar cliente

Remove um cliente através do CPF.

Parâmetros:
  • cpf : CPF do cliente que será removido.
Restrições:

Operações Exclusivas

Operações não triviais que utilizam tabelas relacionadas e JOIN.

GET /cliente/funerais/:cpf
Buscar funerais de um cliente

Busca todos os funerais ligados a um cliente. Esta é uma operação exclusiva com JOIN entre cliente e funeral.

Parâmetros:
  • cpf : CPF do cliente.
Restrições:
  • O CPF deve ser válido.
  • O cliente deve existir.
  • O cliente deve possuir pelo menos um funeral associado.
Exemplo de retorno em caso de sucesso:
{ "msg": "Funerais encontrados com sucesso!", "cliente": "João Silva", "funerais": [ { "id": 1, "nome_falecido": "José Otavio", "data_evento": "2026-09-10", "local": "Cemitério Nossa Senhora do Carmo", "duracao": 4, "pagamento": true } ] }
GET /funeral/servicos/mais-utilizados
Buscar serviços mais utilizados

Retorna os serviços utilizados em funerais, ordenando pela quantidade de vezes que cada serviço foi associado. Operação exclusiva com JOIN e GROUP BY .

Parâmetros:

Não possui.

Restrições:
  • É necessário existir pelo menos uma associação entre funeral e serviço.

Quando dois serviços possuem a mesma quantidade de utilizações, a ordem entre eles pode variar.

Exemplo de retorno em caso de sucesso:
{ "msg": "Serviços mais utilizados encontrados com sucesso!", "data": [ { "id": 1, "nome": "Tanatopraxia", "descricao": "Preparação e conservação do corpo para o velório.", "valor": "500.00", "quantidade_utilizada": "6" }, { "id": 4, "nome": "Urna funerária", "descricao": "Fornecimento de urna funerária para o sepultamento.", "valor": "1500.00", "quantidade_utilizada": "6" } ] }
GET /funeral/periodo/:inicio/:fim
Buscar funerais por período

Busca funerais realizados entre duas datas e retorna também o nome do cliente responsável. Operação exclusiva com JOIN .

Parâmetros:
  • inicio : data inicial informada na própria rota, no formato YYYY-MM-DD.
  • fim : data final informada na própria rota, no formato YYYY-MM-DD.
Restrições:
  • Os dois parâmetros são obrigatórios.
  • A data inicial não pode ser maior que a data final.
  • As datas devem ser válidas para consulta no banco.
  • Deve existir pelo menos um funeral no período informado.
Exemplo de requisição:
/funeral/periodo/2026-09-10/2026-09-12
Exemplo de retorno em caso de sucesso:
{ "msg": "Funerais encontrados com sucesso!", "quantidade_funerais": 2, "data": [ { "id": 1, "nome_falecido": "José Otavio", "data_evento": "2026-09-10", "local": "Cemitério Nossa Senhora do Carmo", "pagamento": true, "nome_primeiro": "João", "nome_sobrenome": "Silva" }, { "id": 2, "nome_falecido": "Antônio Oliveira", "data_evento": "2026-09-12", "local": "Cemitério Municipal", "pagamento": false, "nome_primeiro": "Maria", "nome_sobrenome": "Oliveira" } ] }
GET /funeral/servicos/:id
Buscar serviços de um funeral

Retorna todos os serviços associados a um funeral. Operação exclusiva com JOIN entre funeral, serviço_funeral e serviço.

Parâmetros:
  • id : ID do funeral.
Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O funeral deve existir.
  • O funeral deve possuir pelo menos um serviço associado.
Exemplo de retorno em caso de sucesso:
{ "msg": "Serviços encontrados com sucesso!", "falecido": "José Otavio", "servicos": [ { "id": 1, "nome": "Tanatopraxia", "descricao": "Preparação e conservação do corpo para o velório.", "valor": "500.00" }, { "id": 4, "nome": "Urna funerária", "descricao": "Fornecimento de urna funerária para o sepultamento.", "valor": "1500.00" }, { "id": 5, "nome": "Ornamentação", "descricao": "Decoração e ornamentação do ambiente do velório.", "valor": "400.00" }, { "id": 7, "nome": "Sala de velório", "descricao": "Locação da sala para realização do velório.", "valor": "350.00" } ] }
GET /servico/valor-total/:id
Calcular valor total de um funeral

Soma o valor de todos os serviços associados a um funeral e retorna também os dados principais do funeral e do contratante. Operação exclusiva com JOIN .

Parâmetros:
  • id : ID do funeral.
Restrições:
  • O ID deve ser um número inteiro maior que zero.
  • O funeral deve existir.
